# 路由前的地点解析

这一步发生在任何涉及该点的 `maps_direction_walking`、`maps_direction_bicycling`、
路线计算和地图入口生成之前。每个点只解析一次；后续复用记录，不反复向用户问同一问题。
以下工具名是高德能力参考，具体参数仍需读取当前宿主的 schema。

## 先分清用户指什么

| 输入 | 应做的查询 | 未定位的情况 |
|---|---|---|
| 广场、公园、景点、建筑、商店、车站名称 | 同城 `maps_text_search` → 候选筛选 → 对选中 ID 调 `maps_search_detail` | 只命中同名道路/行政区，或 POI 详情没有可用坐标 |
| 城市＋街道＋门牌 | `maps_geo`，核对返回门牌、城市和层级 | 门牌没有匹配，仅返回道路、区县等范围的中心 |
| 已由用户选中的 POI | 对该 ID 查询详情并核对名称/地址 | ID 或地点身份不一致，不能用别的候选补齐 |
| 明确公园东门、地铁某出口等 | 搜索/详情必须对应指定入口 | 只找到主 POI 或其他入口；不能把中心点重命名成东门 |
| 商圈、街道范围、“我附近” | 询问具体起终点 | 没有足以唯一确定的地点；不用 IP 或账户地址猜 |

**数量不是精度。** 一条 `level=道路` 的地理编码结果，也可能是同名道路而非所需地标。
经纬度格式正确、非零，只证明数字可用，不证明它就是用户想去的地方。
若用户确实指定的是某条道路，也应取得具体门牌/路口，避免把整条路的中心当集合点。

## 筛选后再决定是否询问

1. 以用户明确的城市、地点类型、门牌、分店或入口为约束。
2. 排除已证明不匹配的候选。例如用户说“星湖公园”，同名公交站和地铁站不是公园；
   但用户说“星湖公园站”时不能反过来选公园。
3. 同一 POI ID 的重复条目可以合并；不同 ID 即使同名或坐标接近，也不直接认定是同一点。
4. 一个合理候选：取得并核对详情，说明采用的具体名称/地址后继续。
   用户未指定入口时可用主 POI 标注点，但要标注“入口未确认”，不编造集合出口。
5. 多个合理候选：展示名称、地址、类型/入口的区别，让用户选择后再取最终详情。
   “别问、先算”不解决地点身份。先不为多个候选各算一整圈再让用户选。
6. 没有合理候选或关键字段无法核对：补充检索或询问具体地址，保持未定位。
   缺失城市/类型信息不能被当作已匹配；可以用详情或其他公开地图证据补齐，不凭猜测填字段。

如果同一 POI 的搜索结果与详情在名称、城市或地址上明显冲突，停止使用该点并重新核对；
不能从一条结果拿名称、另一条结果拿坐标拼出“完整地点”。
详情返回限流等错误时遵循服务的重试指引并有限重试，仍失败就报告依赖问题并暂停。

## 点位记录

只保存在会话临时目录或忽略的 `.runtime`，不要提交真实个人行程。
每个用于路由的点记录：

| 内容 | 规则 |
|---|---|
| 用户位置描述 | 保留原话中的城市、地点、入口要求，不扩大到其他地点 |
| 路线点标识 | 与计算输入的 `start_id/end_id/from_id/to_id` 对应 |
| 名称、城市、地址、地点类型 | 来自查询；未返回的内容不要包装为平台字段 |
| POI ID | 来自实际 POI 结果；精确门址无 POI 时留空，不编造以满足地图工具 |
| 坐标与坐标依据 | 记录同一地点详情/精确门址的坐标、原始结果引用、查询时间和层级 |
| 选定依据 | 用户明确选择、唯一语义匹配或精确门址；未获用户明确选择时，不写“用户确认” |
| 入口状态 | 用户未指定/未核实入口，或已匹配所指定入口；不代表入口届时可通行 |

主 POI 是地图参考点，不是精确门口保证。若原始请求含特定入口，入口未匹配就不能通过定位。
坐标为 `0,0`、缺失、非有限数或超出经纬度范围时，不得进入路由；
坐标与城市/地址矛盾时也不能只因数值合法而通过。
保留同一坐标系；不要用麦当劳 `0,0` 覆盖高德坐标。

点位记录与 `route_metrics.py` 的输入分别保存。计算器检查路线点标识的连通关系，
不读取点位记录、不核对 POI 或地理编码层级，**计算成功不等于定位已验证**。

## 点位改变后的失效规则

只要点的 POI ID、坐标或所代表的具体入口改变，就视为地点改变，即使路线点标识不变：

- 废弃所有以该点为起点或终点的旧道路分段，重查距离、耗时和可用的路由信息。
- 环线改变起点时，首段和末段都失效；不能只修第一段。
- 两端点位和原路由证据均未改变的其他分段可以复用。
- 重算整程里程、目标偏差、约束判断、到离时间与营业窗口覆盖。
- 重新核对受影响的沿线补给候选、绕行基线和候选排名。
- 重新生成采用旧点位的地图入口与路线卡片，不把旧链接配上新里程交付。

## 回放例子（合成数据）

用户说“从某市星湖公园出发”，地理编码命中“星湖公园路，level=道路”。
此时下一步是同城公园 POI 搜索，不是步行路由。
若只剩一个公园主 POI，其他都是同名车站，则核对公园详情后说明使用地图标注点；
若仍有两个不同地址的公园，则请用户选择。没有入口依据，不把任一坐标描述为东门。
