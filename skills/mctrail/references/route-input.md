# 路线计算输入

`scripts/route_metrics.py` 使用 Python 3.10+ 标准库，不访问网络，也不读取凭据。
输入文件或 `-`（标准输入）；成功返回 JSON、退出 0；非法输入向 stderr 输出原因、退出 2。
字段拼写错误会报错，不会静默忽略。

## 顶层字段

| 字段 | 类型与含义 |
|---|---|
| `data_kind` | 必需，`live` 或 `demo`；声明来源类型，不代表脚本独立验证过来源 |
| `mode` | `run` 或 `cycle` |
| `shape` | `loop` 或 `point-to-point` |
| `start_id` / `end_id` | 本地路线点位标识；环线相同、点到点不同，不是门店或 POI ID |
| `departure_at` | ISO 8601，必须显式带时区，如 `2026-10-09T23:50:00+08:00` |
| `pace_min_per_km` | 跑步必需，正数，分钟/公里；骑行不填 |
| `target_distance_m` | 可选，目标道路米数；用于显示偏差，不自动成为上限 |
| `max_distance_m` | 可选，用户明确的硬上限；超限作为冲突返回，不能自动抬高 |
| `legs` | 非空、按行进顺序排列的道路分段 |
| `stops` | 可选，停留站点列表；空列表表示不安排停留 |

不接收时长目标字段。时长目标由 Skill 收集配速/速度信息后构造候选，再用计算出的
`travel_seconds` 或 `total_seconds` 对照用户目标；明确比较是否包含停留。
所有数字必须是有限 JSON number，不收字符串、布尔值、负数、NaN、Infinity。

## 每一段 `legs`

| 字段 | 约定 |
|---|---|
| `from_id` / `to_id` | 不同点位；相邻段首尾一致，整条路线首尾与顶层一致 |
| `distance_m` | 正数，真实路网路径长度，已经包含本段绕行 |
| `duration_s` | 骑行必需，正数，来自该骑行路段；跑步按配速重新计算 |
| `source` | 跑步填 `amap_walking`，骑行填 `amap_cycling` |
| `evidence` | 非空，指向宿主本次工具结果/私有快照的引用；不要填 Token 或鉴权 URL |

没有路网查询结果，就不能构造 `live` 分段。脚本检查字段与连通关系，
但不能证明声明的距离来自真实工具，也不处理道路几何或校验坐标。

## 每个 `stops` 项

| 字段 | 约定 |
|---|---|
| `after_leg` | 从 1 开始的整数，第几段结束后停；每段最多一个停留，站点位于该段终点 |
| `name` | 展示名称；现场数据可敏感，禁止把真实个人路线提交到仓库 |
| `dwell_minutes` | 非负数；不隐式使用默认停留时长 |
| `opening_windows` | 必填：未知为 `null`；确认该日期关闭为 `[]`；否则为带日期/时区的区间数组 |
| `hours_evidence` | 窗口不是 `null` 时必填，记录依据；不是仅“当前营业”的状态 |

窗口格式：

```json
{
  "opens_at": "2026-10-09T18:00:00+08:00",
  "closes_at": "2026-10-10T00:20:00+08:00"
}
```

窗口起止必须是完整日期时刻，结束晚于开始。相邻或重叠区间会合并，
有间隔的营业窗口不会合并。到达时刻等于关门时刻视为关闭；
停留结束恰好等于关门时刻视为窗口可覆盖，但用户还应考虑实际入店/服务限制。
这里检查的是输入窗口，不保证未来营业不变，也不证明座位或堂食可用。

## 输出解释

- 每段运动/停留向上取整到秒，再逐段累加，避免少算时间；十进制数字参与时间与距离计算。
- `distance_error_m`：实际减目标，正数表示超过目标；未提供目标则为 `null`。
- `within_distance_limit`：是否在硬上限内；未提供上限则为 `null`，不是默认满足。
- `finish_at`：包含沿途所有停留，以出发时区表示的预计结束时刻。
- `hours_status`：`covers_visit`（输入窗口覆盖整个停留）、`closes_during_stop`、
  `closed_at_arrival` 或 `unknown`。
- `has_known_conflict`：仅判断明确超限/窗口冲突；`false` 绝不等于路线安全、门店可用或所有条件已满足。
- `warnings`：包括未知营业时间、超限、窗口冲突，以及 `demo` 的不可导航提醒。

结果不是路线搜索或安全验证器。不要只看退出码：退出 0 也可以包含超限、关门或未知状态。

## 离线例子

从 Skill 所在目录运行（Windows）：

```powershell
python .\scripts\route_metrics.py .\examples\night-loop.json
```

这是虚构的 8.2 公里闭合路线，不提供实际地点或导航链接。预期 10 月 10 日
00:14 到 B，计划停至 00:29，但营业窗口到 00:20，状态应为 `closes_during_stop`。
含停留的预计结束时间为 00:54:12，不能推荐为符合原停留要求的方案。
