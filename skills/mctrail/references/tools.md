# 数据与工具约定

本文件是能力映射，不是接口完整副本。先发现宿主当前 MCP tools，再读取要调用的
工具 schema；工具被移除、参数变化或权限不足时明确失败，不能照抄过期示例调用。

## 高德地图 MCP

官方文档：
- https://lbs.amap.com/api/mcp-server/summary
- https://lbs.amap.com/api/mcp-server/create-project-and-key
- https://lbs.amap.com/api/mcp-server/gettingstarted

官方远程接入地址为 `https://mcp.amap.com/mcp?key=<本地配置的Key>`，
使用 Streamable HTTP，Key 的服务平台选择“Web 服务”。
Key 出现在连接 URL 中，因此不要把完整鉴权 URL放进日志、截图或公开文件。
这里不安装 npm 包，也不直接处理凭据。各客户端环境变量展开方式不同，必须以宿主说明为准。

| 需要的能力 | 输入来自哪里 | 使用边界 |
|---|---|---|
| 地理编码 | 用户确认的城市与完整地址 | 核对门牌与返回层级；地标名称先做 POI 搜索，不能以同名道路的坐标替代 |
| 步行路径 | 已确认的起终点坐标 | 跑步候选路网，不是跑步专用或照明保证 |
| 骑行路径 | 已确认的起终点坐标 | 跑步、驾车结果不能混作骑行距离/时间 |
| 关键词/周边/详情搜索 | 用户城市与地点描述，或已确定路线附近的坐标 | 先按城市/类型筛选再核对详情，完成点位记录后才路由；直线距离不作为最终路程 |
| 专属地图/导航入口 | 已确认的点位和顺序 | 核实链接是整条行程还是只到一个终点 |

路由前必须完成 [地点解析](place-resolution.md)，不能只凭地理编码坐标存在就开始计算。
多个搜索结果不一定需要问：唯一语义匹配的 POI 核对详情后可继续；
多个合理候选仍需用户选择。用户指定的入口不能被主 POI 替代。

地图提供两点间的路网结果；带补给点和环线时，必须逐段查询。
原路返回与真正不同路径的闭环要区分；不能只凭端点相同宣称路线不重复。
保留同一服务使用的坐标系，不混入手表轨迹、其他地图或未经转换的坐标。
输出预计运动时长，不承诺配速、道路开放、夜间照明或门店服务一定符合实际。

## 麦当劳中国 MCP

官方说明：https://github.com/M-China/mcd-mcp-server

远程服务：`https://mcp.mcd.cn`；Bearer Token 放在宿主本地连接配置中。

| Tool | 本版用途与重要参数 |
|---|---|
| `now-time-info` | 获取时间背景；用户计划的出发日期不能被“现在”覆盖 |
| `query-nearby-stores` | `searchType=2`、用户确认的 `city`、沿线位置 `keyword`、`beType=1` |
| `query-meals` | 仅用户想了解补给餐品时：真实 `storeCode`、`orderType=1`、`beType=1`，不传 `beCode` |
| `query-meal-detail` | 仅需要套餐组成时，从菜单取得真实餐品 `code` |
| `calculate-price` | 仅用户需要报价时；按当前 schema 构造商品，金额以官方结果为准 |

本版不会调用 `create-order`、`cancel-order`、积分兑换/抽奖、领券、地址新增等写入工具。
不为做路线规划读取收藏门店、账户配送地址、历史订单等非必要信息。
服务器提供哪些其他工具，不等于本 Skill 得到了使用它们的授权。

## 合并数据时的规则

1. 高德 `POI ID`、麦当劳 `storeCode`、路线内使用的 `start_id/from_id/to_id` 是不同命名空间。
2. 地址和位置能唯一对上，才给门店附加“已核实为此麦当劳门店”的状态；
   仅同名/最近不能证明是同一家。存在冲突时展示待确认项，不继续给该店报价。
   麦当劳坐标若为 `0,0` 或缺失，不能进入路由；按名称和门牌匹配高德 POI 详情，
   保留各自 ID 与证据，不能从不匹配的地点借坐标。
3. 到店窗口以准确到日期的营业信息为依据；当前 `businessStatus` 只能说明查询时刻。
   不把 `reservationTimeOptions` 当营业时间，也不把预约可取餐当可在店内休息。
4. 不能推定营业至午夜时跨哪一天。无明确日期、周期规则或当天适用证据时，
   计算输入使用 `opening_windows: null`；只有明确确认当天不营业才用 `[]`。
5. 每条最终道路分段保留原始响应位置、查询时间与来源，计算单位统一为米和秒。
6. 已开展高德步行路由与麦当劳门店查询的跑步环线实测，结果为部分通过；
   定位修复后的完整复测、其他场景与地图几何仍待验证。本参考不声称所有门店都返回营业时间、坐标或堂食状态。

## 失败处理

| 情况 | 对用户的处理 |
|---|---|
| 地图未接入/鉴权失败 | 无法产生已验证道路路线；给出配置说明，不输出示例当真 |
| 地图路径为空/不连通 | 排除候选并说明，不能拿直线补段 |
| 地标命中道路、地点详情失败或仍有多个合理候选 | 先完成地点解析或询问，未定位前不开始涉及该点的路由/计算 |
| 麦当劳未接入 | 补给无法核实；用户同意后可仅提供地图路线 |
| 同名门店无法唯一匹配 | 保留未确认状态；不借用另一家店的时间或餐品 |
| 营业窗口缺失 | 标为未知，与已确认关门严格区分 |
| 限流/服务错误 | 遵守服务重试指引，有限重试；仍失败就报告，不无限循环 |

安装模板位于仓库根目录 `mcp-config.example.json`，它不是已认证的连接。
